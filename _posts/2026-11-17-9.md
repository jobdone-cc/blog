AI 模型的 API 協定，就是程式和模型之間約定好的對話格式。這篇說明它是什麼、為什麼許多服務都改用 OpenAI 或 Anthropic 的格式，以及為什麼號稱相容的服務，接上之後還是可能要調整程式。

**重點整理：API 協定為什麼存在、解決什麼問題**

- **它是什麼**：程式和模型之間「怎麼說話」的約定，例如問題要怎麼包裝、回答會長什麼樣子。
- **解決的問題**：如果每家的格式都不同，換一個模型就得重寫一次程式。大家採用共通格式之後，換模型就像換一顆同規格的燈泡。
- **它解決不了的事**：協定只統一了外層格式，各個模型的回答方式和各家的支援程度仍然不同。說「相容」，只代表接得上，不代表結果完全一樣。
- **對你的意義**：選工具或服務時，先看它支援哪幾種格式。支援的格式越常見，日後越好轉換。換過去之後，還是要實際測試自己用到的功能。

## 用插座來理解

台灣的電器插頭都長得差不多，所以不管買哪一牌的吹風機，插上牆壁就能用。如果每家電器的插頭都不一樣，那就麻煩了。

API 協定就是 AI 模型的插座規格。你的程式要把一段對話送給模型，就得照一定的格式寫：哪一句是使用者說的，哪一句是系統設定，回應要不要一個字一個字傳回來。模型回覆時也用固定格式。雙方事先講好，才接得起來。

## 為什麼大家都學 OpenAI 和 Anthropic 的格式

OpenAI 很早就推出 Chat Completions 這套格式，大量的程式、套件和工具都照它來寫，它慢慢成為事實上的通用規格。後來 OpenAI 又推出 Responses API。Anthropic 的 Messages API 也隨著 Claude 系列普及，被許多工具採用。

其他模型供應商發現，與其要開發者學一套新格式，不如直接相容這些常見格式。結果就是：同一段程式，只要把網址和模型名稱換掉，就能改接另一家的模型。

## 實際例子：Hugging Face 的新路由

Hugging Face 這次改用 OpenRouter 來派送語言模型的請求。不管後面實際由哪一家供應商執行模型，新的路由器都支援 OpenAI 的 Chat Completions、Responses，以及 Anthropic 的 Messages 三種格式。

所以像 Claude Code、Codex、OpenCode 這類程式開發代理工具，只要改一下設定，就能改用 Hub 上的開放模型。這就是共通協定的好處：工具和模型被拆開了，可以各自挑選。

## 都說相容，為什麼還是會卡住

插頭的比喻只說對了一半。插頭一樣，能保證電送得進去，卻不保證每台電器的用法都一樣。API 協定也是這樣。它統一的是「信封」的格式，信裡的內容怎麼寫、對方怎麼讀，仍然各有差異。所以常見的情況是：請求送得出去，回應也收得回來，但收回來的東西還要再整理一次，或是跑起來比預期慢、比預期貴。原因大致有以下幾個。

**第一，中間有一層翻譯。** 每個開放模型在訓練時都有自己的對話格式，用什麼記號區分系統設定、使用者和模型的發言，各家都不一樣。服務商收到 OpenAI 或 Anthropic 格式的請求後，要先轉成模型自己的格式，模型回答後再轉回來。這層翻譯做得好不好，取決於服務商。翻得不準時，回答品質就可能變差，甚至出現格式錯亂。

**第二，三種協定本身就不一樣。** Anthropic 的 Messages 把一則回覆拆成好幾個區塊，文字、思考過程、工具呼叫各放一塊。OpenAI 的 Chat Completions 則是一則訊息加上另外附帶的工具呼叫欄位，Responses 又是另一種結構。從一種格式轉成另一種時，有些資訊沒有對應的位置，只能捨棄或硬塞進去。

**第三，工具呼叫最容易出問題。** 代理工具很依賴模型「呼叫工具」的能力，例如讀檔案、執行指令。有些模型的工具呼叫會被服務商整理成標準欄位，有些卻以一般文字的形式回傳，程式得自己解析。解析失敗，代理工具就會卡住或重試，時間和費用都跟著增加。

**第四，思考過程放的位置不同。** 會先推理再回答的模型，有的把思考內容放在獨立欄位，有的直接混在回答文字裡，用特殊標記包起來。後者你得自己把思考內容切掉，否則它會被當成答案顯示出來，或被存進對話紀錄，白白占用下一輪的輸入量。

**第五，有些參數會被悄悄忽略。** 同一個參數，例如要求輸出嚴格符合某個 JSON 結構，有的服務商真的會強制遵守，有的只是盡量做到，有的乾脆不支援，也不會回報錯誤。程式表面上照常運作，但結果不一定可靠，只好再加一道檢查和重試。

**第六，快取影響效率。** 長對話如果能重複利用已經處理過的開頭內容，就能省時間又省錢。但各家快取的做法不同，有的要明確標記，有的自動處理，有的不支援。如果路由器把同一段對話一下送到甲、一下送到乙，快取就失效，每一輪都得從頭計算。Hugging Face 的新路由特別設計成會讓同一段對話留在持有快取的供應商那裡，也建議開發者為每段對話送一個固定的識別碼。連路由器都要專門處理這件事，可見協定相容和實際效率是兩回事。

所以「支援 OpenAI 格式」比較像一張入場券：讓你不必從零開始寫，但不保證每個功能都照你預期的方式運作。真正要換模型或換服務商時，請把自己實際會用到的功能逐項測過，特別是工具呼叫、思考內容、結構化輸出和長對話的速度。
